# Park to Podium — Product Vision

## What We Are Building

Park to Podium is a responsive management game for desktop and mobile browsers.
The player develops a disc golf park by building and upgrading holes and
facilities, managing resources, developing fictional players, and arranging
tournaments. The park's characteristics should affect tournament results.

The game must have its own visual identity, rules, and assets. Other management
games may inspire the overall experience, but they must not be copied.

## Core Game Loop

1. View and inspect the park.
2. Select a hole or facility.
3. Spend resources to build or upgrade it.
4. Arrange a tournament or activity.
5. Calculate results based on the players and the park's characteristics.
6. Award rewards and create new choices.
7. Save the game and continue developing the park later.

The first milestone is a small, local, and playable version of this loop.

## Long-Term Goal

The long-term goal is a persistent, asynchronous online game with user accounts.
Players' parks will be stored on the server and may later be connected through
public parks, leaderboards, weekly challenges, clubs, and seasons. Players will
not need to be online at the same time; real-time multiplayer is not part of the
product vision.

The project should also serve as a portfolio project demonstrating knowledge of
frontend and backend development, databases, testing, deployment, and secure
system design.

## Priorities

1. Understandability and learning.
2. Correct and testable game rules.
3. Maintainability and clear boundaries of responsibility.
4. Security and game integrity.
5. An accessible and responsive user experience.
6. Simple and cost-effective operations.
7. Scaling only when real needs exist.

## Not Now

- A backend, accounts, or remote database before the local core loop works.
- Real-time multiplayer.
- Public parks, leaderboards, clubs, or seasons.
- An advanced graphics engine or extensive animations.
- Features that do not contribute to the next playable milestone.
